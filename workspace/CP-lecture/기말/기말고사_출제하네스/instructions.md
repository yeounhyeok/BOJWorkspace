"중간고사때 쓰던 instruction 을 기말 범위(8~14장)로 바꾼 것. 이거 참고해서 기말고사 모의고사를 만들면 됨."

너는 C프로그래밍 과목 기말고사 출제자다.

다음 시험 정보를 기준으로 기말고사 대비 모의고사를 만들어라.

시험 정보:
- 범위: C언어 8장 ~ 14장 (함수, 포인터, 문자열, 구조체, 파일 입출력, 동적 메모리, 전처리/매크로)
- 배점: 총 30점 만점
- 문제 수: 반드시 8문제
- 형식: 필답 고사
- 채점 기준: 정답이 아니어도 설명, 접근 과정, 코드 구조가 맞으면 부분 점수를 줄 수 있도록 구성
- 난이도: 실제 기말고사 대비용. 너무 쉽지만은 않게, 개념 이해와 코드 작성 능력을 함께 확인할 것
- 교재: C언어 콘서트(천인국) 기준. 게시판 교재 예제(static.c, swap2.c, char_ptr.c, pointer_to_st.c, malloc2.c, macro1.c 등)의 소재를 활용하면 좋다.

출제 우선순위 (실제 기말 응시한 선배 제보 반영 — 중요):
- ★ 킬러 문제는 반드시 9장 포인터에서 낸다. 가장 어렵고 배점도 가장 크게(5점) 배정한다. (포인터+배열+함수 call by reference를 엮은 심화 문제)
- ★ "이번 기말 범위의 기본 개념을 두루 엮어, 코드를 보고 예상 출력값을 쓰는" 종합 출력 예측 문제를 반드시 1문제 넣는다. (교수님이 매 시험 1문제씩 내는 시그니처 유형. 중간고사 때는 비트 연산자 출력값 예측이 나왔음 → 기말은 8~14장 기본 개념으로)
- ★ "다음 코드에서 무엇이 잘못되었는지(버그) 찾아 고치시오" 유형의 버그 찾기 문제를 반드시 1문제 넣는다.
- ▼ 파일 입출력(12장), 전처리/매크로(14장), 동적 메모리(13장)는 비중을 낮춘다. 실제 기말 본 선배 제보상 이 세 부분은 거의/전혀 안 나왔다고 함. 완전히 빼지는 말되(제보가 100% 정확하다는 보장은 없으므로), 가벼운 개념 문제 1개 정도로 압축한다.
- 결과적으로 포인터 > 함수 ≈ 문자열 ≈ 구조체 > 파일/동적/전처리 순으로 비중을 둔다.

출제 범위와 반영할 내용:
8장 함수:
- 함수 원형(prototype), 정의, 호출의 구분과 역할
- 반환형(void vs int/double), `return`의 의미
- 지역변수 / 전역변수 / static 변수의 범위(scope)와 수명(lifetime)
- static 변수의 값 유지 (호출마다 1,2,3 ... 식으로 누적) 출력 예측
- 같은 이름일 때 지역변수 우선(shadowing)
- 재귀 함수 동작 과정 추적 (factorial 등)

9장 포인터:
- 주소 연산자 `&` 와 간접 참조 연산자 `*`
- 포인터 선언과 `*p`를 통한 원본 변수 값 변경
- call by value vs call by reference (swap 예제)
- 배열 이름 == 첫 번째 원소의 주소 (`a == &a[0]`)
- 포인터 산술 (`p+1`은 자료형 크기만큼 증가)
- 배열을 함수 인자로 넘기면 원본이 바뀐다는 점

10장 문자열:
- 문자열 = char 배열 + 끝의 널 문자 `'\0'`
- `char s[] = "..."` (수정 가능) vs `char *p = "..."` (수정 불가) 차이
- string.h 함수: `strlen`, `strcpy`, `strcat`, `strcmp` (특히 strcmp는 같으면 0)
- `scanf("%s")` (공백 못 받음) vs `gets_s` (공백 받음)
- 2차원 문자 배열 (문자열 배열)

11장 구조체:
- struct 선언, 변수 선언, 초기화
- 멤버 접근: 변수는 `.` , 포인터는 `->` (`p->x == (*p).x`)
- 구조체 배열
- 구조체를 함수 인자/반환값으로 사용 (값 복사)
- typedef로 별칭, union(메모리 공유), enum(0부터 자동 증가)

12장 파일 입출력:
- 파일 처리 3단계: fopen → (NULL 검사) → 입출력 → fclose
- fopen 모드 r / w / a / rb / wb 의 의미 (특히 w=덮어쓰기 vs a=이어쓰기, b=이진)
- 텍스트 입출력(fprintf/fscanf/fgets/fputs) vs 이진 입출력(fread/fwrite)
- fseek / ftell 로 파일 위치 이동 및 크기 구하기

13장 동적 메모리:
- 정적 배열 vs 동적 할당의 차이 (크기 결정 시점)
- malloc 4단계: (자료형*)형변환 + 개수*sizeof + NULL 검사 + free
- 동적 배열 할당과 사용
- 동적 구조체 할당 (포인터라 멤버 접근은 `->`)
- free를 안 하면 메모리 누수

14장 전처리/매크로:
- 전처리는 컴파일 전 단순 텍스트 치환
- `#define` 단순(상수) 매크로
- 함수형 매크로와 괄호의 필요성 (`SQUARE(2+3)` 함정)
- 조건부 컴파일 `#ifdef` / `#else` / `#endif`
- 비트 매크로(SETBIT/CLEARBIT/TESTBIT) 등

문제 구성 지침:
- 반드시 총 8문제로 출제한다.
- 총점은 반드시 30점이 되게 배점한다.
- 개념 문제와 구현 문제를 적절히 섞는다.
- 단순 암기만 묻지 말고, 코드 실행 결과 예측, 오류 수정, 짧은 설명, 직접 구현 문제를 골고루 포함한다.
- ★ 9장 포인터 심화(포인터+배열+함수 call by reference 엮은) 킬러 문제를 반드시 포함하고, 배점을 가장 높게(5점) 준다.
- ★ 9장 포인터 기본(call by value vs call by reference, swap) 문제도 따로 1문제 포함한다. (포인터는 총 2문제)
- ★ 8~14장 기본 개념을 엮은 "코드 보고 예상 출력값 쓰기" 종합 출력 예측 문제를 반드시 포함한다.
- ★ "코드에서 무엇이 잘못되었는지 찾아 고치기"(버그 찾기) 문제를 반드시 포함한다. (포인터/문자열/구조체에서 흔한 실수를 소재로)
- 11장 구조체 문제는 반드시 포함한다.
- 파일 입출력(12장)·동적 메모리(13장)·전처리/매크로(14장)는 합쳐서 가벼운 개념 문제 1개로만 다룬다. (저비중. 매크로 괄호 함정은 이 경량 문제의 소재로 써도 됨)
- 코드 작성 문제는 너무 긴 프로그램이 아니라 시험장에서 손으로 쓸 수 있는 수준으로 낸다.
- 1~7장(반복문/배열 등 기초)만 묻는 문제는 내지 않는다. 단, 8~14장을 풀기 위해 배열/반복문을 도구로 쓰는 것은 허용한다.
- C++ 문법이 아닌 C언어 문법을 기준으로 출제한다.

3번. [포인터] 9장: call by value vs call by reference, swap 코드 작성/추적 - 4점

채점 기준 작성 방식:
- 각 문제마다 만점 기준을 적는다.
- 부분 점수를 어떻게 줄 수 있는지 구체적으로 적는다.
- 예를 들어 코드 구현 문제는 다음처럼 나눈다:
  - 변수/포인터/구조체 선언이 적절함
  - 입력/출력 처리가 맞음
  - 조건문 또는 반복문 구조가 맞음
  - 포인터/멤버 접근(`*`, `&`, `.`, `->`) 사용이 맞음
  - malloc/free, fopen/fclose 등 자원 처리가 맞음
  - 최종 결과가 정확함
- 설명형 문제는 핵심 키워드가 들어가면 부분 점수를 줄 수 있게 한다.
- 출력 예측 문제는 줄 단위로 맞은 만큼 부분 점수를 준다. (전체 다 맞아야 점수 주는 식 금지)
- 버그 찾기 문제는 ① 버그 위치를 찾음 ② 왜 틀렸는지 설명 ③ 올바르게 고침 — 세 단계로 나눠 부분 점수를 준다.

출제 스타일:
- 교수님 필답 고사처럼 간결하고 직접적인 문장으로 출제한다.
- 학생이 손으로 답안을 작성할 수 있는 분량으로 낸다.
- 너무 장황한 시나리오 문제는 피한다.
- 구현 문제는 `#include <stdio.h>`와 `int main(void)`를 사용하는 기본 형태를 권장한다.
- 배열/구조체 문제에서는 크기가 너무 큰 것을 쓰지 말고 3~5개 정도로 제한한다.

반드시 포함해야 하는 대표 소재:
- 포인터로 원본 변수 값을 바꾸는 `*p = 값;`
- swap을 call by reference(`swap(int *px, int *py)`, `swap(&a, &b)`)로 구현
- 배열 이름이 첫 원소의 주소(`a == &a[0]`)라는 점
- `char s[] = "..."`와 `char *p = "..."`의 수정 가능 여부 차이
- `strcmp`는 두 문자열이 같으면 0을 반환한다는 점
- 구조체 포인터의 멤버 접근 `p->멤버` == `(*p).멤버`
- fopen의 `"w"`(덮어쓰기)와 `"a"`(이어쓰기) 차이
- malloc 4단계: 형변환 + 개수*sizeof + NULL 검사 + free
- static 변수가 호출마다 값이 유지되어 1, 2, 3 ... 으로 출력되는 점
- `#define SQUARE(x) x*x` 와 `#define SQUARE(x) ((x)*(x))` 에서 `SQUARE(2+3)`의 결과 차이(11 vs 25)
- `#ifdef`로 코드가 조건부로 컴파일되는 동작
- (버그 찾기 소재) swap에서 `swap(a, b)`처럼 주소를 안 넘긴 실수, `if (x = 0)` 대입/비교 혼동, 구조체 포인터에 `p.멤버`로 접근한 실수, `char s[10]; s = "abc";`처럼 배열에 대입한 실수, `strcmp` 결과를 거꾸로 해석한 실수
- (출력 예측 소재) `char c = 'A'; printf("%d", c);` → 65 같은 문자-아스키 변환, `*(p+i)` vs `p[i]`, `*p+1` vs `*(p+1)`

최종적으로 실제 학생이 30~50분 정도 풀 수 있는 8문제짜리 모의고사를 생성하라.
